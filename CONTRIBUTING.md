# Как участвовать

По-русски. Issue, pull request, обсуждение — на русском языке, и это не
формальность: проект существует потому, что русскоязычному разработчику
приходится объяснять свою задачу на чужом языке в чужом трекере. Английский
тоже примут, никто не развернёт.

## Быстрый старт

```bash
git clone https://github.com/theasder/orakul.git orakul && cd orakul
cd app && swift build          # Swift 5.9+ (Xcode 15+)
swift test                     # тесты приложения
cd ../mvp && swift test        # тесты ядра: словарь, поиск, коннекторы
cd .. && npm test              # тесты страницы, текстов и идентичности
```

Руками ставить не нужно ничего. Но первая сборка `app/` скачивает 27 пакетов:
четыре прямых — WhisperKit, FluidAudio, MCP SDK, ViewInspector — и двадцать три,
которые тянутся за ними (swift-nio, swift-crypto, async-http-client и прочая
серверная обвязка). Столько же строк `Fetching` вы и увидите; проверено сборкой
из чистого клона 2026-08-13. Нужна сеть и несколько минут. `mvp/` и `npm test` не тянут ничего: в
`package.json` зависимостей нет вовсе, тесты страницы гоняет сам Node.

**Если добавили файл в `mvp/Sources/OrakulCore` и сборка приложения его «не
видит».** Ошибка выглядит как `cannot find <Тип> in scope`, хотя файл на месте
и импорт есть. SwiftPM держит список файлов зависимости-по-пути в кеше и нового
файла там не замечает; дата на манифесте не помогает, список считается по
содержимому. Лечится одной командой:

```bash
cd app && swift package clean && swift build
```

**Если сборка установщика останавливается на профиле нотаризации.** Сообщение
называет команду: `xcrun notarytool store-credentials meetgpt-notary`. Пароль
вводит человек — он не хранится в репозитории и не должен. Проверка стоит
первой, до компиляции: 2026-08-13 профиль пропал из связки, и выяснилось это
после шести минут сборки arm64.

Сборка установщика делает это сама (`app/build.sh`), а обычная — нет: чистка
стоит две минуты, и платить их на каждой правке не за что.

## Что попадёт в проект быстрее всего

1. **Коннектор к российскому сервису.** Это главный дефицит и главная причина,
   по которой orakul вообще отдельный продукт. Битрикс24 подключён 2026-08-13,
   но по документации, а не на живом портале — если у вас есть портал, самое
   ценное сейчас это одна команда из §2.0.1 плана и ответ, работает ли поиск.
   Обход списка закончен, перепись — в §2.0.3 плана: четыре подключены, четыре
   нет, у каждого «нет» названа причина. **Мегаплан отпадает** (нет
   долгоживущего ключа, вход логином и паролем), **Аспро.Cloud и WEEEK** ждут
   одного и того же: описания метода списка задач с параметром поиска и формой
   ответа. Найдёте его — это работа на день, и она нужна. Образец — `mvp/Sources/OrakulCore/RussianTrackers.swift`,
   чертёж с объяснением каждого решения — `docs/RESEARCH-AND-PLAN.md`, §2.2.
2. **Слова, которых не хватает словарю.** `RussianLexicon` чинит расшифровку
   после распознавания, и его таблица собрана по одному замеру. Термин, который
   у вас на звонках слышится неправильно, — это готовая строка в неё.
3. **Русские тексты.** В приложении ещё остались английские строки. Каждая —
   отдельная маленькая правка.

## Правила, о которые ломаются чужие пулл-реквесты

**Не заявляйте того, чего нет.** Кнопка «Подключить» к сервису, у которого нет
подходящего API, хуже отсутствия кнопки. Прежде чем добавлять коннектор,
проверьте в документации вендора метод, адрес, параметр поиска и форму ответа —
и сошлитесь на неё в комментарии. Два сервиса из первой пятёрки трекеров
выпали именно на этой проверке, и это правильный исход.

Сюда же относится пустая выдача вместо отказа. Не всякий сервис пользуется
кодами HTTP: Битрикс24 отвечает `200` и кладёт отказ в тело, поэтому тело
проверяется до разбора списка. И пустой список принимается только знакомой
формы: ответ без единого известного ключа — отказ, а не «ничего нет». Иначе
отозванный ключ покажется человеку как «задач не нашлось», и он заведёт вторую
поверх существующей. Подробнее — §2.2 плана, пункты 5.1 и 5.2.

**Каждая функция закрыта тестом.** Не «есть тесты», а: тест падает, если
функцию сломать. Тест, проверяющий выдуманный адрес, проходит и не значит
ничего.

**Тесты не ходят в сеть.** HTTP передаётся снаружи (`RussianTrackers.HTTP`),
ключи — в фальшивую Связку ключей (`InMemoryKeychain`). Тест, который ходит в
Яндекс Трекер, проверяет Яндекс Трекер.

**Ничего платного.** Тарифов, лимитов и платных экранов в orakul нет; это
закреплено `NoTariffsTests`. Функция, доступная «только на плане», в проект не
попадёт.

**Данные не покидают компьютер.** Запись, расшифровка и поиск считаются
локально. Кнопка, которой нужна наша сеть, не проходит проверку при сборке.

Один зелёный прогон — не результат. Набор большой и идёт параллельно, поэтому
тест, берущий общее состояние у соседа, падает не каждый раз. 2026-08-13 таких
нашлось два: один проверял предусловием сессию, которую выставляют другие
наборы, второй требовал конкретного первого места в ранжировании, а оно зависит
от того, успел ли построиться индекс эмбеддингов. Оба падали примерно раз в пять
прогонов и оба ничего не сообщали о продукте.

Ловятся они циклом с сохранением вывода, а не `swift test | grep`: в живом
выводе виновник дважды не нашёлся.

```bash
for i in 1 2 3 4 5; do
  swift test > /tmp/run$i.log 2>&1
  grep -q "failed after" /tmp/run$i.log && { grep -n "recorded an issue" /tmp/run$i.log; break; }
done
```

Правили тесты — прогоните весь набор несколько раз.

**Скорость проверяется отдельной командой.** Бюджеты задержки — поиск по году
звонков, восстановление терминов в двухчасовой расшифровке — закрыты тестами,
которые обычный `swift test` пропускает: на занятой машине они меряют не код, а
соседний компилятор. Правите `DecisionRecallService`, `GlossaryRestore` или
индекс — прогоните их сами:

```bash
cd app && CRUXWING_PERF=1 swift test --filter Performance
```

Замер на этой машине 2026-08-13: поиск по 250 звонкам — 2,04 с (лучшее из
трёх), восстановление двухчасовой расшифровки укладывается в послезвонковый
бюджет. Зелёный обычный прогон об этом не говорит ничего: без переменной оба
набора помечаются пропущенными и попадают в общее число как пройденные.

**Секреты — только в Связке ключей.** Ключи провайдеров и токены трекеров живут
в Keychain (`ProviderKeyStore`, `RussianTrackerStore`), никогда в UserDefaults и
никогда в коде. Пустая строка убирает запись, а не сохраняет пустоту: иначе
очищенное поле оставляет мёртвый ключ, и сервис выглядит настроенным.

## Прогон части проверок

`swift test --filter Имя` при опечатке в имени печатает

```
✔ Test run with 0 tests passed after 0.001 seconds.
```

и возвращает ноль. Опечатка выглядит точно так же, как успешный прогон, — и
это не теория: за одну ночь я купился дважды, один раз решив, что проверка не
ловит мутацию, хотя она просто не запускалась.

```bash
bash scripts/test-filter.sh mvp RussianCaseSearchTests
bash scripts/test-filter.sh app AgendaCheckServiceTests
```

Скрипт падает, если под фильтр не попало ни одной проверки. Фильтровать надо по
имени структуры набора: кириллические названия из `@Test("…")` в фильтр не
попадают.

## Если запускаете сборку образов

`cd app && bash dist-all.sh` собирает две архитектуры и идёт около десяти минут.
Пока она идёт, репозиторий заморожен: правка любого файла в `app/Sources` или
`mvp/Sources` роняет её с `input file ... was modified during the build`, а
коммит посреди сборки даёт два образа, заявляющих разные коммиты.

Проверять надо не глазами:

```bash
bash scripts/build-running.sh && echo "нельзя править" || echo "можно"
```

Скрипт узнаёт сборку по рабочему каталогу процесса, а не по строке запуска:
сборка стартует как `cd app && bash dist-all.sh`, и пути в её командной строке
нет вовсе — шаблон `pgrep -f "orakul/app.*dist-all\.sh"` не совпадал никогда и
молча разрешал править. Чужая сборка из `/tmp` при этом за свою не принимается.
Обе стороны закрыты проверками в `test/build-running.test.mjs`.

Безопасно во время сборки: `test/*.mjs`, `public/*.html`, `README.md`, `docs/`,
`scripts/` — в отпечаток исходников входят только два каталога `Sources`.

## Оформление

Коммиты: `тип: что сделано` — `feat`, `fix`, `refactor`, `docs`, `test`,
`chore`, `perf`. Первая строка по-русски, до 72 символов.

Комментарии в коде объясняют **почему**, а не что: «что» видно из кода.
